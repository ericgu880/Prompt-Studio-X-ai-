# PromptStudio 上线前完整审查与发布门禁

审查日期：2026-07-16
审查范围：macOS 桌面端、商业授权服务、运营管理后台、支付与邮件 Webhook、数据库、构建签名、CI、产品体验与后续订阅化路径。

## 结论

当前状态：**代码整改完成，带外部条件通过（DONE WITH CONCERNS）**。

本轮已修复会直接造成付费损失、授权失效或运营误操作的缺陷；代码可以进入签名包和预生产环境验证，但在下方 P0 发布门禁全部完成前，不能对外正式收费上线，也不能宣传已经支持订阅。

## P0 发布门禁

以下事项依赖 Apple、Lemon Squeezy、Resend、DNS 或生产环境，仓库内不能代替真实配置：

- [ ] 安装有效的 Developer ID Application 证书及私钥，完成 Hardened Runtime、时间戳、公证和 Gatekeeper 验证。
- [ ] 生成并妥善备份生产 Ed25519 私钥、许可证 pepper 和数据加密密钥；将匹配公钥注入 Release App。
- [ ] 确认桌面永久授权的真实 HTTPS 购买地址，并通过 `PROMPTSTUDIO_PURCHASE_URL` 注入。未配置时购买按钮会保持关闭。
- [ ] 确认一年更新权益的执行矩阵：到期后是否允许安装同大版本更新、跨大版本如何升级、权益期内取得的新大版本是否永久可用；随后补齐服务端校验和回归测试。当前只记录、签名和展示权益日期。
- [ ] 确认支持、隐私政策、服务条款和退款政策的正式 URL 与客服责任人。
- [ ] 部署独立 PostgreSQL，执行全部 Prisma migration，并验证备份、PITR、恢复演练和告警。
- [ ] 配置生产 DNS/HTTPS、Resend 域名、Lemon Squeezy 商品映射及 Webhook 签名密钥，并完成真实沙盒/低金额订单闭环。
- [ ] 在已解锁的真实 Mac 上完成 VoiceOver/键盘、浅色/深色、多尺寸窗口、媒体预览和许可证流程人工验收。
- [ ] 用最终签名包验证 App 实际连接预期的本地资料库和生产授权服务，不使用 Debug 环境覆盖。

任一门禁失败，应停止发布并回滚到上一个已签名版本，不应通过关闭校验绕过。

## 本轮已修复

### 产品与商业化

- 桌面端不再把“购买”硬编码到另一套云订阅定价页。Release 仅接受构建时注入、格式正确的 HTTPS 地址；缺少配置时明确显示购买通道未开放。
- 授权文案统一为“永久授权 + 一年版本更新权益 + 本地离线凭证”，避免把更新权益误导成软件到期。
- 明确当前售卖能力只有永久授权和设备席位；更新权益目前可记录/签名/展示但尚未执行跨大版本规则，`subscription` 只是数据模型预留，两者都不能被提前宣传成已完整实现。
- Release 不再自动创建内部演示文件夹、标签和素材，防止用户删除后再次出现；Debug 仍可保留演示数据用于开发。

### 桌面端体验与 UI

- 区分“资料库为空”和“筛选无结果”，分别提供创建内容与清除筛选的下一步操作。
- “全部”导航会同时重置类型、标签、收藏、日期和高级条件，避免界面看似回到全部但结果仍被隐藏。
- 高级筛选重新打开时保留当前条件；设置底部按钮改为明确的保存/恢复默认，不再出现内部 MVP 文案。
- 购买入口、授权状态徽标和永久授权说明完成中文化，并复用现有设计色彩与控件样式。
- 生产授权服务地址不再接受环境变量或 UserDefaults 覆盖；开发覆盖限定在 Debug 构建。

### 支付、授权与数据库一致性

- Lemon Squeezy 事件名以已签名请求体为准；Header 存在但不一致时拒绝请求。
- 退款使用真实 Webhook 事件 ID 幂等，避免把订单 ID 当事件 ID 后吞掉后续全额退款。
- 新增持久化 `CommerceOrderState`：退款先到、订单后到或多实例并发时，最终状态仍会对账为退款并撤销授权。
- 全额退款采用单调状态，不会被较早的部分退款或重复事件反向覆盖。
- 限流错误正确返回 429 和 `Retry-After`，不再被通用异常映射成 500。
- 证书服务启动时从私钥派生公钥，并与配置的 raw/SPKI 公钥逐字节比对；不匹配即拒绝启动。

### 后台服务与运维

- `/health` 保留为进程存活检查，新增 `/ready` 数据库与最新关键 migration 检查；旧 schema 不会假绿切流。
- 生产环境强制独立的 session、CSRF、HMAC 等密钥、HTTPS 管理后台源、非零可信代理 hop、有效数值区间、至少一个唯一商品映射，并禁止在当前一体化部署中关闭 Worker。
- Worker 轮询异常会被捕获并报告，不再形成未处理 Promise 拒绝；SIGTERM/SIGINT 会停止新轮询，并在有界时间内等待在途支付和邮件任务后再断开数据库。
- Prisma CLI 纳入生产依赖，生产镜像可执行 `prisma migrate deploy`；新增 `.dockerignore` 防止本地依赖和 `.env` 进入构建上下文。
- Resend 邮件状态改为单调转换，已送达邮件不会被乱序 delayed 事件降级。

### 私有运营管理后台

- 统一 `AdminApiError`，展示服务端消息和 requestId；只有 401 才跳转登录，网络错误和 500 不再造成登录循环。
- 429 显示重试等待，403 提示刷新会话；登录入口与错误提示完成产品化中文文案。
- 禁止停用最后一个有效 owner，也禁止当前 owner 直接停用自己，降低永久锁死后台风险。
- Web 后台和 CLI 停用 owner 共享 PostgreSQL 事务级 advisory lock，并发操作也会至少保留一个有效 owner。
- CSV 对以 `=`, `+`, `-`, `@` 开头的单元格做安全前缀处理，避免表格公式注入。
- 删除继承自 Ant Design Pro 的公开预览、部署机器人、CNAME 和演示说明；CI 改为当前项目实际使用的 npm 流程。
- 生产依赖中的 DOMPurify 固定到已修复版本；开发工具链遗留依赖风险单独列入技术债。

### 质量门禁

- 新增 macOS、授权服务与管理后台的最小 CI，覆盖构建、单元测试、商业流程、脚本策略和生产依赖审计。
- 为退款乱序、重复事件、签名密钥不匹配、429、readiness、生命周期、Worker 恢复、owner 保护、CSV 注入、邮件状态和 Release 文案增加回归测试。
- 构建脚本会拒绝缺少生产公钥、无效购买 URL、ad-hoc 签名或不符合预期 Team ID 的 Release 包。

## 产品与订阅策略建议

### 近期可售产品

建议先把当前版本定义为“本地优先的 macOS 永久授权产品”：

- 用户的数据与媒体留在自己选择的本地资料库。
- 一次购买获得当前大版本永久使用权和约定期限内的更新权益。
- 设备席位、恢复、离线证书和退款撤销由授权服务管理。

这与现有实现一致，解释成本和运营风险最低。

### 后续订阅方向

订阅不应只是把 `licenseType` 改成 subscription。建议将订阅价值放在持续产生服务器成本的能力上，例如云同步、AI 额度、团队协作、跨设备历史和托管备份，同时保留本地永久使用权作为信任锚点。

正式开发订阅前至少需要：

- provider subscription/customer ID、账期、取消时间、宽限期、欠费/暂停/恢复状态模型；
- `subscription_created/updated/cancelled/expired/payment_failed` 等事件状态机与乱序对账；
- 套餐/额度/席位的服务端授权矩阵，而非仅靠客户端 Feature Gate；
- 升降级、按比例计费、退款、税务、发票、续费提醒与客服操作规范；
- 用户可见的账单门户、取消入口、数据导出和订阅终止后的降级策略；
- 指标：购买转化、激活成功率、退款率、邮件送达率、付费留存、席位冲突和支持工单。

这些规则会改变定价、法律承诺和用户权益，必须由产品负责人确认后再实现。

## 仍保留的 P1/P2 技术债

- 激活失败审计目前随主事务回滚，需改为事务外的脱敏失败记录，否则失败率会偏低。
- 恢复接口为防邮箱枚举统一返回 200 是正确的，但仍需补充不含明文邮箱的结构化内部日志。
- 已加密支付原文、nonce、challenge、session、recovery token 和证书的保留期/清理任务尚未确定；应先确认法律与运营保留期。
- Resend 状态已单调化，但 `svix-id` 还没有持久化去重表。
- 当前管理后台只有 owner 角色。引入客服或运营账号前，必须先实现服务端 RBAC、MFA/访问网关和操作范围矩阵。
- Swift 6 严格并发下仍需逐步清理 `NSImage` 等非 Sendable 类型的警告。
- 一年更新权益尚未在激活/刷新时按 `appVersion`、`majorVersion` 与 `updatesUntil` 执行。该规则会直接改变用户永久使用权，需先确认上方产品矩阵，不能由工程实现自行猜测。
- 桌面端完整键盘焦点、VoiceOver 标签、媒体失败态和窄窗口布局仍需真实设备人工测试。
- 开发依赖审计仍报告：授权服务 5 项（3 moderate、1 high、1 critical），管理后台 54 项（10 low、26 moderate、17 high、1 critical），来源主要是 Vitest/Vite 与 Umi/Ant 构建工具链；两边 `npm audit --omit=dev` 均为 0。生产依赖审计应保持发布门禁，开发链升级应独立排期，避免在上线前大版本换框架。

## 发布判定

代码层面具备进入预生产验收的基础。正式收费上线的最终判定必须同时满足：

1. 本文 P0 发布门禁全部勾选；
2. CI、生产 migration、依赖审计和最终签名包验证全部通过；
3. 一笔真实购买到激活、一笔退款到撤销的端到端演练通过；
4. 产品页面、App 文案、购买渠道和客服口径对“永久授权/更新权益/尚未支持订阅”的描述一致。
