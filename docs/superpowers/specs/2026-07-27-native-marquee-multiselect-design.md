# PromptStudio 原生框选、多选删除与整组拖拽设计

## 背景

PromptStudio 中间资源网格已经支持单击选择、Command 单击切换、Shift 连选、单项拖拽和批量移入回收站，但当前实际启用的原生 `NSCollectionView` 网格没有框选能力，拖拽到文件夹时也只携带一个资源 ID。

本次改造为中间资源网格补齐 Finder 风格的框选、多选删除和整组拖拽，同时保留当前原生瀑布流的滚动性能、布局、卡片交互和资料库数据结构。

## 目标

- 从网格空白区域按住鼠标左键拖动，框选一个或多个资源。
- 普通框选替换当前选择，按住 Command 框选追加到当前选择。
- 选中多个资源后，Command + Backspace 将它们统一移入回收站。
- 从任一已选卡片开始拖动，将全部已选资源一次移动到目标文件夹。
- 交互、反馈和快捷键安全边界与 macOS Finder 保持一致。
- 在当前约 280 条资源及更大资料库中保持平滑滚动和框选反馈。

## 非目标

- 不切换到备用 SwiftUI 瀑布流。
- 不给文件夹卡片增加框选或多选能力。
- 不支持跨应用拖出多个真实文件。
- 不改变回收站的永久删除与确认逻辑。
- 不新增数据库表、偏好设置或公开接口。
- 不修改 Quick Look、预览页或右侧信息栏交互。

## 方案选择

采用原生 AppKit 方案：在当前 `FlippedMasonryCollectionView` 上实现框选手势和选框绘制，通过 `MasonryCollectionGridView.Coordinator` 与现有 `AppState.selectedIDs` 同步。

未采用以下方案：

- 切回已有 SwiftUI 网格：框选代码可复用，但会放弃当前原生网格的滚动和复用性能。
- 在原生网格上覆盖 SwiftUI 手势层：需要跨坐标系命中，且容易拦截滚动和卡片拖拽。

## 交互规范

### 框选

1. 仅当鼠标左键按下点位于资源网格空白区域时，才进入潜在框选状态。
2. 鼠标移动超过系统拖拽阈值后显示选框；未超过阈值便松开时视为空白单击。
3. 空白单击清空资源选择和文件夹卡片选择。
4. 普通框选以空集合为基线，实时选择与选框相交的资源卡片。
5. 按住 Command 开始框选时，以开始手势时的 `selectedIDs` 为基线；命中的资源追加到该集合，不切换或取消原选择。
6. 资源卡片只要与选框相交即命中，不要求被完整包围。
7. 文件夹卡片不参与命中，也不会因框选改变其状态。
8. 框选开始后清除当前文件夹卡片选择。
9. 按 Escape 取消正在进行的框选，恢复手势开始前的资源选择和文件夹卡片选择。
10. 鼠标靠近可视区域顶部或底部时自动滚动；选框终点随滚动后的文档坐标持续更新。

### 选框视觉

- 填充：现有主操作强调色，约 `16%` 不透明度。
- 描边：同一强调色，约 `72%` 不透明度，`1pt`。
- 圆角：`8pt`。
- 选框位于卡片之上但不拦截事件。
- 框选过程中沿用现有卡片选中描边，不引入新的卡片样式。
- Reduced Motion 不影响选框位置更新；选框本身不增加缩放或弹性动画。

### 点击与拖拽

- 保留单击选择、Command 单击切换和 Shift 连选。
- 从已选卡片开始拖动时，拖动当前全部已选资源，包括不在当前可视区域内的已选资源。
- 从未选卡片开始拖动时，先将选择替换为该卡片，再只拖动该资源。
- 多选时不执行网格内部手动排序，避免将整组拖动误解为单卡重排。
- 拖拽预览使用起始卡片的缩略图，并显示资源数量标记。
- 文件夹的现有悬停和可放置反馈继续使用。

### 删除快捷键

- 仅 Command + Backspace 或 Command + Forward Delete 触发批量移入回收站。
- 仅在至少存在一个未删除的已选资源时生效。
- 搜索框、Prompt 编辑器、文本字段或其他文本输入控件处于编辑状态时不拦截按键。
- 操作调用现有“移入回收站”语义，不永久删除、不弹确认框。
- 回收站中的已删除资源不会通过同一快捷键二次永久删除。

## 架构与职责

### `FlippedMasonryCollectionView`

负责原生鼠标事件和选框表现：

- 判断按下点是否位于空白区域。
- 记录手势起点、当前点、修饰键和是否超过拖拽阈值。
- 在自己的文档坐标系中维护标准化选框。
- 绘制选框并驱动边缘自动滚动。
- 将 begin/change/end/cancel 事件通过明确的闭包接口交给 Coordinator。

该视图不直接读取或修改 `AppState`，避免把产品状态耦合进 AppKit 视图。

### `MasonryCollectionGridView.Coordinator`

负责选择语义和视图同步：

- 在框选开始时快照资源选择和文件夹卡片选择。
- 使用 `MasonryCollectionLayout.indexPathsForItems(in:)` 获取相交条目。
- 过滤文件夹条目，只生成资源 ID 集合。
- 根据普通或 Command 模式计算下一选择集合。
- 通过 `AppState.selectItems(ids:primaryID:)` 更新唯一选择源。
- 仅刷新前后集合对称差对应的可见卡片。
- 取消框选时恢复开始前的快照。

### `MasonryCollectionLayout`

继续作为卡片几何信息的唯一来源。现有 `indexPathsForItems(in:)` 已能按矩形查找相交条目；实现时可以补充一个便于测试的纯几何辅助函数，但不建立第二份布局缓存。

### `AppState`

`selectedIDs` 和 `selectedID` 继续作为全应用唯一选择状态。新增一个面向文件夹投放的批量入口：

```swift
moveItems(_ itemIDs: [String], toFolderID folderID: String)
```

该入口负责：

- 去重并过滤不存在、已删除或已在目标文件夹中的资源。
- 按当前网格视觉顺序处理有效资源。
- 使用一个数据库事务完成全部资源更新。
- 成功后只刷新一次内存状态和过滤结果。
- 保留有效的主选择；如果资源因当前筛选条件离开视图，则选择下一可见资源。
- 显示一次“已移动 N 个项目到〈文件夹〉”提示。

单资源移动调用可复用该入口，避免两套行为逐渐分叉。

### 内部拖拽数据

新增 PromptStudio 私有 pasteboard 类型，内容为版本化的资源 ID 数组。原生图片和 Markdown 卡片统一生成该数据；文件夹 Drop Handler 优先读取多资源数据，并保留对旧单字符串资源 ID 的兼容。

数据在拖拽开始时生成：

- 起始卡片已选：使用当前 `selectedIDs`。
- 起始卡片未选：先只选中该卡片，再生成单 ID 数组。

文件夹一次消费完整数组，避免多个独立 Drop Provider 导致重复刷新、部分顺序错误或多条 Toast。

## 数据一致性与失败处理

- 批量文件夹移动应使用数据库事务：任一数据库写入失败时回滚整组，内存状态保持不变，并显示一次错误信息。
- 拖拽开始后资源被删除或不存在时，投放前过滤无效 ID；如果没有有效资源，拒绝投放且不刷新。
- 目标文件夹不存在时拒绝投放并显示错误，不把资源移动到根目录。
- 资源已在目标文件夹中时将其视为无变化；若整组均无变化，提示“所选素材已在当前文件夹”。
- 框选期间发生数据集或布局重载时，结束当前框选并保留最后一个有效选择，避免使用过期 IndexPath。
- 自动滚动计时器在 mouseUp、Escape、视图移除和窗口失焦时必须停止。
- 框选事件更新在主线程执行；只在命中集合变化时写入选择状态。

## 可访问性

- 框选不会改变现有卡片 VoiceOver 标签和单项操作。
- 批量拖拽预览的数量提供可访问性描述，例如“拖动 5 个项目”。
- Command + Backspace 成功后的现有 Toast 继续报告实际处理数量。
- 鼠标框选是对现有键盘 Command/Shift 多选的补充，不替代键盘路径。

## 测试设计

### 单元与组件测试

- 选框从四个方向拖动时都能标准化为正确矩形。
- 相交命中、边缘接触命中以及文件夹过滤正确。
- 普通框选替换集合，Command 框选执行集合并集。
- Escape 恢复资源选择和文件夹选择快照。
- 多资源拖拽编码、解码、去重和旧单 ID 兼容。
- 批量移动过滤无效项、已删除项和同文件夹项。
- 批量移动数据库失败时整体回滚。
- Command + Backspace 修饰键匹配正确，文本输入激活时不触发资源删除。

### 回归检查

- 原生网格必须接入框选处理，不能通过关闭 `useNativeMasonryCollectionView` 绕过实现。
- 多选拖拽必须使用批量资源 payload，不能在文件夹上循环触发单资源 Toast 和完整刷新。
- 现有单击、Command 单击、Shift 连选、双击预览、右键菜单和单项操作保持有效。
- 现有手动排序在零或单选时保持有效，多选时保持禁用。

### 手工验收

1. 从空白处向四个方向拖动，确认选框、命中和卡片描边同步。
2. 普通框选后再次普通框选，确认旧选择被替换。
3. 按 Command 框选，确认旧选择保留且新命中项追加。
4. 单击空白清空；框选途中按 Escape 恢复之前选择。
5. 跨越可视区域边缘框选，确认自动滚动且不会失控。
6. 从已选卡片拖到不同文件夹，确认全部资源一次移动。
7. 从未选卡片拖动，确认仅移动该卡片。
8. 将部分已在目标文件夹的多选组拖回该文件夹，确认无重复写入。
9. 按 Command + Backspace，确认全部未删除选择进入回收站且没有永久删除。
10. 在搜索框和 Prompt 编辑器内按相同快捷键，确认只执行文本编辑。
11. 检查图片、视频、音频、Markdown 等资源卡片行为一致。
12. 在约 280 条及更大数据集中快速框选、自动滚动和重复拖拽，确认无明显掉帧或选择闪烁。

### 构建与发布验证

- Swift Debug 构建。
- 核心自动化测试。
- Smoke Test。
- 现有发布 UI 检查。
- 在实际资料库中人工检查批量移动和回收站恢复，确认数据库与文件资源没有丢失。

## 完成标准

- 当前原生瀑布流中可以稳定完成 Finder 风格框选。
- 多选集合与卡片视觉、右侧信息栏及现有菜单保持一致。
- Command + Backspace 安全地批量移入回收站。
- 任一已选卡片可把完整选择组一次移动到文件夹。
- 文本编辑、单项拖拽、手动排序和预览没有回归。
- 全部自动与手工验证通过后提交并推送功能代码。
